# 月饼营养核验库说明

月饼营养核验库需要在多方参与、事件顺序不稳定和服务重启的情况下保持记录一致。每条记录有所属方、状态和递增版本，所有状态变化写入审计表；请求键用于抵御重复提交，事务失败时整次写入回滚。

## 一致性设计

- **换算与校验先行**：标签入库前统一折算为每 100 克规范值，缺失或单位异常的标签标记为无效并产生告警，无效标签在试算、发布、下单三个入口都被拒绝。
- **导入幂等**：`batch_id` 相同的导入整单回放；告警表以 `(商品, 标签版本, 问题码)` 唯一约束兜底，重复导入同一批商品不会重复生成告警。
- **发布阻断**：发布在单事务内对全部授权画像做过敏原冲突核验，冲突则整体回滚并抛 `PublishBlocked`（HTTP 422），阻断事件单独提交审计，保证“阻止发布”而非“只提示”。
- **历史钉版**：订单快照保存规则版本、标签版本与下单时画像；规则注册新版本只影响后续发布与订单，`GET /orders/{id}` 用钉住版本重算并与快照比对。
- **授权边界**：画像的 `scopes` 决定哪些健康关注参与计算，未授权关注不进入阈值判断，只在结果中显式列出。
- **重启一致**：所有状态存于 SQLite 文件库，写入经 `BEGIN IMMEDIATE` 串行化，进程重启后结果与审计记录保持一致。
